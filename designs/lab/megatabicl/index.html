MegaTabICL: Efficient Scaling of Tabular Foundation Model Pretraining

Ayush Kaushal, Daria Yasafova, Irina Rish

Published on OpenReview 29 Sept 2026 · Presenting in Paris, Dec 13 2026

OpenReviewPDF CodeBibTeX

We characterize the TFM pretraining workload to build MegaTabICL, an exact 3.86x-cheaper implementation of TabICLv2 pretraining, and use it for a first billion-parameter scaling study showing the compute-optimal parameter count growing with budget.

3.86x

lower stage-1 cost

Reference 28M run on 4xH100: 20.96 to 5.43 H100-days.

17.35

H100-days for 1B params

Full 500K-step stage 1, 37x Base, below the 28M reference.

0.2B

compute-optimal size

At TabICLv2's own stage-1 budget, 7x its size.

24

models, 5M to 1B

Six budgets, one non-repeating table sequence, 27.5 H100-days in total.

Three mismatches with standard pretraining practice

01

Heavy-tailed prior generation

Tables are generated on CPU with median 218 ms and p99 2893 ms; 37% of attempts are rejected, using 36% of sampler time. MegaTabICL keeps several batches in generation so the slowest table no longer stalls a step.

02

Heterogeneous input shapes

Rows and columns vary by orders of magnitude per table, which breaks compiled graphs. Shape-independent dynamic compilation, shape-agnostic attention kernels and a cost model for balancing micro-batches across ranks.

03

Compute in low-parameter layers

The column embedder and row interactor hold under 5% of parameters but over half of step time. 78% of tensors hold 2.5% of parameters, so a grouped optimizer step goes from 158.9 ms to 14.2 ms.

The only deviation from the reference recipe: QASSMax stays in FP32 and moves from Muon to AdamW, which keeps BF16 training stable.
